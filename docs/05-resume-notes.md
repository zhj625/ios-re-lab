# 05 · 简历描述与面试提纲

## 项目名称

**iOS IPA 静态逆向与 ARM64 二进制补丁自动化**

## 简历描述

- 使用 REA、Python 与 Capstone 分析约 95.6 MB iOS IPA，解析 68.6 MB ARM64 Mach-O 的 Load Command、Objective-C Runtime 元数据与 Swift Reflection 字段，定位广告展示、奖励回调和版本更新控制流。
- 重建关键业务状态机与 ARC 对象生命周期，设计82个等长指令补丁，覆盖4个常规展示入口、11组激励业务回调及1个强制更新分支，复用原有 reward/close 路径维持页面状态和资源释放语义。
- 开发版本安全的 Python 补丁器，实现 SHA-256 白名单、逐指令 preimage、ARM64 `B/BL` 编码、非覆盖式 IPA 重打包与1029个归档项差异验证；广告与激励业务版本完成实际安装验证。

## 30秒介绍

这是一个完整的 iOS 静态逆向项目。我先通过 REA 和 Python 脚本解析 Mach-O、Objective-C 类元数据与 Swift 字段描述，再结合 ARM64 反汇编恢复广告、奖励回调和版本检查的控制流。补丁没有把相关函数全部改成 return，而是复用原程序的 reward 与 close 路径，并保持 ARC 的 retain/release 语义。最后将分析结果做成版本绑定的自动化补丁器，加入哈希、原始指令和 ZIP 完整性校验，防止补丁误用于其他版本。

## 面试追问

### 为什么不能把所有入口直接改成 RET？

部分入口同时承担页面转场或业务状态恢复。直接返回可能导致启动页无法进入主界面，或激励业务永远不解锁。因此需要识别并复用应用已有的成功与关闭路径。

### 如何确定 `forceUpdate` 对应偏移 `0x60`？

Swift Reflection 字段描述给出了字段顺序，Objective-C ivar metadata 给出实例偏移，最终机器指令使用 `LDRB [X8,#0x60]` 读取布尔值，三个来源相互印证。

### 如何避免固定偏移误伤新版本？

工具先校验完整主程序 SHA-256，每个补丁写入前再校验 expected bytes。任意一层不匹配都会终止，并且输出文件不能覆盖输入文件。

### 如何验证没有修改其他资源？

重新打包后比较输入和输出的完整 ZIP 路径集合与每个文件内容。记录中1029个路径一致，只有主 Mach-O 内容发生变化。

### 项目还能如何扩展？

- 自动从 Mach-O 元数据发现类与回调，而不是维护固定偏移；
- 为新旧版本生成函数级 diff；
- 增加真实强更条件下的端到端测试记录；
- 将补丁清单导出为可审计 JSON；
- 增加 Mach-O code signature 状态检查。
